# О чём презентация: объяснение на русском

## Коротко

Доклад о том, как заставить ИИ хорошо делать работу. Его две части повторяют название «Prompt Logic & AI Agent Tool Chaining».

1. **Prompt Logic (логика промпта).** Как правильно ставить ИИ задачу. Промпт — это не просьба «напиши что-нибудь», а программа на обычном языке: цель, условия «если… то…», формат ответа, примеры, самопроверка.
2. **Tool Chaining (цепочки инструментов).** Как дать ИИ «руки», то есть инструменты. Тогда он сам выполняет задачу по шагам: ищет данные, считает, пишет отчёт, отправляет сообщение. Такой ИИ называется **агентом**.

**Для кого:** для людей, которые уже пользуются ИИ и слышали про агентов.

**Что они унесут:**
- схему MAKTAB для хороших промптов;
- понимание, как устроен агент;
- 8 готовых скиллов для Claude.

**Главная мысль:** модель одна и та же, результат решает логика запроса и то, какие инструменты вы ей дали.

**Длительность:** 45 минут, из них около 43,5 по плану и немного запаса.
- Вступление: ~3,5 мин.
- Часть I: ~16 мин.
- Часть II: ~19 мин.
- Финал: ~5 мин.

## Вступление

**1. Титульный слайд.**
- На экране: название собирается из летящих частиц.
- Что сказать: «Сегодня две темы: как правильно ставить задачу ИИ и как дать ему руки, чтобы он стал агентом. Заголовок собрался из частиц, и модель тоже читает текст кусочками, токенами».

**2. Эксперимент: одна модель, два промпта.**
- Промпт А: «Напиши маркетинговую стратегию для кофейни». Ответ общий, он подойдёт любой кофейне в любом городе.
- Промпт Б: цель (Instagram-план на 4 недели), бюджет 5 млн сумов, аудитория студенты, условие «если идея дороже бюджета, предложи дешевле», формат таблицей. Ответ — конкретный план по неделям с KPI и расходами в рамках бюджета.
- Вывод на экране: «Model bir xil edi. Logika boshqa edi», то есть «модель та же, логика другая». Это главная мысль всего доклада.
- Если есть интернет, кнопка «Jonli sinash» отправляет оба промпта в Claude вживую.

**3. Маршрут.** Пять остановок: Промпт → Логика → Цепочка → Инструменты → Агент. Внизу экрана всё время видна линия-«метро»: где мы сейчас.

## Часть I. Логика промпта

**4. Заставка части I.**

**5. Модель читает токены, а не слова.**
- На экране живой токенизатор: можно ввести любую фразу, и она разобьётся на кусочки.
- Узбекский текст занимает в 2–2,7 раза больше токенов, чем английский. Значит, память модели заполняется быстрее, а запрос стоит дороже.
- Модель каждый раз выбирает следующий кусочек по вероятности, и промпт управляет этими вероятностями.

**6. Промпт — это программа на обычном языке.**
- Слева код, справа тот же смысл обычными словами:
  - переменная → «Имя клиента»;
  - `if` → «Если…»;
  - цикл → «Для каждого отзыва…»;
  - `return` → формат ответа.
- Вывод: модель — исполнитель, вы — программист. Неточность в промпте даёт ошибку так же, как баг в коде.

**7. MAKTAB — 6 слоёв хорошего промпта.**
- Пример: служба поддержки интернет-магазина отвечает на жалобу. Промпт разбирается на 6 слоёв MAKTAB, и под каждый слой есть строчка из примера.
- Вопрос залу: «Какие буквы пропали в вашем последнем промпте?»

**8. «Agar» (если) — логика внутри промпта.**
- Промпт превращается в блок-схему:
  - если данных не хватает, не выдумывай, а спроси;
  - если возврат до 14 дней, пришли порядок возврата;
  - если после 14 дней, предложи другой вариант;
  - если техническая проблема, задай 2 вопроса;
  - иначе передай оператору.
- Главное правило: у каждого «если» должно быть своё «иначе». Там, где его нет, модель начинает выдумывать (галлюцинации).

**9. Tartib (порядок): теги и схема.**
- **Вход.** Разделяем промпт тегами: документ отдельно, правила отдельно, вопрос отдельно. Длинный документ ставим наверх, вопрос в конец.
- **Выход.** Просим ответ строго по JSON-схеме: ответ, источник, уверенность. Такой ответ может прочитать программа, и это мостик ко второй части.

**10. Конкретный пример.**
- Один хороший пример объясняет лучше, чем десять правил.
- На экране мишень: без примеров ответы разбросаны, с тремя разными примерами они собираются в центр.
- Предупреждение: модель копирует из примера всё, включая длину и даже ошибки.

**11. Reasoning-модели (думающие).**
- Раньше писали «думай пошагово» и расписывали каждый шаг. Сегодня модели думают сами, поэтому им нужно давать не шаги, а цель, требования к результату и ограничения.
- Параметр **effort** регулирует, сколько модель думает:
  - low — быстро и дёшево;
  - high или max — глубже, но медленнее и дороже.

**12. Baholash: промпт без тестов — это гадание.**
- На слайде: слева промпт службы поддержки, справа 10 настоящих писем клиентов.
- Клик 1: прогоняем промпт на всех письмах. Хорошо 6 из 10: в трёх грубый тон, в одном модель выдумала цену.
- Клик 2: ошибки подсвечиваются красным, в промпт добавляются две строки: «тон вежливый» (K) и «цену бери только из списка» (A).
- Клик 3: второй прогон, хорошо 9 из 10.
- Тип ошибки подсказывает, какой слой MAKTAB чинить. В реальной работе берут 30–50 примеров.

**13. Лаборатория промптов.**
- Вживую добавляем слои MAKTAB по одному: промпт растёт, оценка растёт с 12 до 96.
- Кнопка отправляет промпт в Claude. Можно взять товар из зала.

**14. Вместо одного огромного промпта — цепочка.**
- Если всё запихнуть в один промпт, модель делает всё наполовину.
- Правильно так:
  - каждый шаг решает одну задачу (сбор → анализ → текст → проверка);
  - между шагами идёт чёткий формат данных;
  - после анализа стоит проверка качества.
- Так видно, где ошибка, и каждый шаг можно тестировать отдельно.
- Переход: «Теперь дадим этой цепочке руки».

## Часть II. Цепочки инструментов и агенты

**15. Заставка части II.**

**16. У модели есть мозг, но нет рук.**
- Три слабости модели:
  - её знания заморожены на дате обучения;
  - она ошибается в точных расчётах;
  - она не может действовать сама: отправить письмо, записать в базу.
- Решение — инструмент (tool). У него три части: имя, описание (это тоже промпт!) и схема параметров.

**17. Как работает вызов инструмента (tool calling).**
- Пример: «Будет ли завтра дождь в Самарканде?» Схема пошагово:
  1. Приложение отправляет вопрос в Claude вместе со списком инструментов.
  2. Claude не отвечает сразу, а просит вызвать `get_weather(Samarqand)`.
  3. Ваш код вызывает API погоды.
  4. Результат возвращается в Claude.
  5. Claude отвечает: «Да, 70%, возьмите зонт».
- Главное: модель только **просит** вызвать инструмент, а выполняет его ваш код. Значит, контроль у вас.

**18. Агент = модель + инструменты + цикл.**
- Семь строк кода — сердце любого агента: подумал → сделал → посмотрел результат → повторил.
- У агента обязательно должны быть условия остановки:
  - задача выполнена;
  - кончился лимит шагов;
  - нужно подтверждение человека.

**19. Chaining: 6 шаблонов цепочек** (по статье Anthropic «Building Effective Agents»).
1. Последовательная цепочка: результат шага передаётся в следующий, между шагами проверка.
2. Routing (маршрутизация): определяем тип запроса и отправляем по нужному пути.
3. Параллельная работа: несколько моделей работают одновременно.
4. Главная модель и исполнители: главная делит задачу и раздаёт её.
5. Автор и проверяющий: один пишет, другой проверяет, пока не получится хорошо.
6. Автономный агент: план, инструменты и момент остановки выбирает сама модель.

Первые пять — workflow, путь рисуем мы. Шестой — агент, путь выбирает модель. Совет: начинайте с простого, агент — последнее средство.

**20. Собираем агента (анимация, есть и видео MP4).** Агент собирается по деталям:
- **LLM (мозг):** принимает текст и отдаёт текст.
- **Системный промпт:** роль, цель и правила. Здесь работает MAKTAB.
- **6 инструментов:** мероприятия, погода, калькулятор, валюта, отчёт, сообщение.
- **Память:** краткосрочная (контекст) и долгосрочная (файлы и база).
- **Цикл:** подумал → сделал → посмотрел.
- **Запуск.** Задача: «Найди AI-мероприятия в Ташкенте в октябре, проверь погоду, выбери лучшее и отправь команде». Агент сам строит план, запрашивает погоду на три даты параллельно, делает отчёт и отправляет его. Справа виден журнал каждого вызова.
- **Финал:** «Bu — agent», то есть «это и есть агент».

**21. Живой агент.**
- Тот же агент работает по-настоящему: Claude сам выбирает, какие инструменты вызвать и в каком порядке.
- Можно взять задачу из зала: другой город или бюджет.
- Без интернета показывается записанный прогон.

**22. Описание инструмента — это тоже промпт.**
- Плохой пример: `search` — «ищет».
- Хороший пример:
  - точное имя;
  - описание, как для нового сотрудника: когда использовать и когда нет;
  - текст ошибки, который подсказывает, что исправить;
  - меньше инструментов, но точных;
  - короткий результат.

**23. MCP — «USB-C для ИИ».**
- 3 приложения и 5 сервисов без стандарта требуют 15 отдельных подключений, с MCP — 8.
- MCP — открытый стандарт от Anthropic, с декабря 2025 года он передан в Linux Foundation.
- Сервер MCP даёт три вещи: инструменты (действия), ресурсы (данные) и промпты (шаблоны).

**24. Контекст — это ограниченный рабочий стол.**
- Всё, что видит модель, должно поместиться на «стол»: системный промпт, описания инструментов, история, документы, результаты. Когда стол переполнен, качество падает.
- Четыре приёма:
  - сжимать старую историю;
  - подгружать только нужное;
  - раздавать части задачи субагентам;
  - использовать скиллы, которые раскрываются только когда нужны.
- Итог: prompt engineering — это что сказать, context engineering — что модель увидит.

**25. Где агент ломается и как защититься.**

| Проблема | Защита |
|---|---|
| Бесконечный цикл | Лимит шагов и бюджета |
| Выдуманные параметры | Проверка по схеме и понятный текст ошибки |
| Prompt injection: чужой текст с командами внутри результата | Правило «чужой текст — это данные, а не команды», минимальные права |
| Неверный выбор инструмента | Точное описание, меньше инструментов |
| Необратимые действия | Только с подтверждением человека |
| «Чёрный ящик» | Журналы и тесты |

## Финал

**26. Карта инструментов 2026.**
- Где тестировать промпты: Claude Console и аналоги.
- SDK для агентов: Claude Agent SDK, OpenAI Agents SDK, LangGraph, CrewAI и другие.
- Без кода: n8n, Make, Dify.
- Агенты для программирования: Claude Code, Cursor.
- Стандарты: MCP, A2A, Agent Skills.
- Мониторинг и тесты: Langfuse, LangSmith, Promptfoo.
- С чего начать: промпт в Claude Console → цепочка в n8n или Agent SDK → инструменты через MCP → мониторинг в Langfuse.

**27. Бонус: 8 скиллов для Claude.**
- Готовые папки-навыки: пишут промпт по MAKTAB, лечат промпт, составляют тесты, подбирают примеры, делают JSON-схему, разбивают задачу на цепочку, пишут описания инструментов и системный промпт агента.
- Скачиваются по QR-коду, пока там заглушка «tez orada», то есть «скоро».

**28. Кто собрал эту презентацию?**
- Ответ: ИИ-агент. Спикер ставил задачу, направлял и проверял.
- На экране реальные этапы сборки: поиск фактов → план → код → проверка по скриншотам → видео → публикация. Там же цифры: 29 слайдов, 7 399 строк кода, 4 261 кадр видео.
- Всё, о чём говорили, сработало на этой самой презентации.

**29. Итоги и вопросы.** Три мысли:
1. Промпт — это программа: пишите по MAKTAB и проверяйте тестами.
2. Инструмент — это руки модели, и его описание — тоже промпт.
3. Начинайте с простого: промпт → цепочка → workflow → агент.
